# dsh-inject 实施计划

## 用户路径

1. 在 Web 设置页创建多个预设（「＋ 新建预设」可建任意多个）。
2. 为每个预设添加替换规则：关键词或正则、替换文本，角色可勾选用户 / 助手 / 工具返回。
3. 为预设配置「开头构造回合」，角色可选系统 / 助手 / 用户 / 工具。
4. 在会话里用 `/inject on <预设名...>` 启用（可同时启用多个）；`/inject off` 关闭；`/inject` 查看当前状态；`/inject clear` 全部关闭。
5. 输入 `/inject-turn` 回车打开现场 dialog，现场编辑构造回合，可载入/保存模板，确认后插入到当前位置。带参数的 `/inject-turn <模板名|JSON>` 仍由宿主命令直接处理。
6. 输入栏不放置任何常驻按钮。

## 语义约定

- **自动替换只作用于模型请求**：实现为 `llm/stream` 上改写一份请求副本，原始会话消息与界面显示不变。
- **开关零副作用**：启用状态是进程内、按会话分区的集合，不写入会话日志；关闭后无残留。
- **默认关闭**：任何会话初始都没有启用预设。
- **会话级**：`/inject` 的状态只影响当前会话。
- **请求侧构造回合**：预设的开头回合与手动注入都进入请求前缀，不产生 transcript 事件。
- **system 位置**：构造的 system 内容与请求原有 system 消息合并，保证请求仍以 system 开头。

## 架构

| 关注点 | 位置 |
| --- | --- |
| 配置模型（预设/规则/回合/模板） | `src/schema.js` |
| 请求改写（只改文本块、按角色筛选） | `src/transform.js` |
| 会话级状态（启用集合、待注入队列） | `src/session-state.js` |
| 宿主插件（命令、web 路由、llm/stream 改写） | `src/index.js` |
| 设置页 | `src/client/settings-panel.jsx` |
| 现场 dialog 与浮层宿主 | `src/client/inject-dialog.jsx` |
| 客户端命令装饰与槽位注册 | `src/client/index.jsx` |
| dialog 开关状态 | `src/client/dialog-state.js` |
| 配置读写与样式 | `src/client/config-store.js`、`src/client/styles.js` |

现场 dialog 由客户端命令装饰驱动：`ctx.commandUi.decorate({ name: "inject-turn", ui: { kind: "action" } })` 在裸调用时翻转会话开关，挂在 `conversation.input.overlay` 的组件据此渲染；因此输入栏没有常驻按钮。

配置通过 `configForms` 的 `inject` 命名空间读写，字段声明为 `.volatile()` 以支持热更新。

## 已知限制

- 未做 transcript 上的替换可视化标记（用户明确暂缓）。
- 会话级启用状态是进程内的：重启后回到默认关闭。
- 现场 dialog 依赖 `webServer` 与 `connection` 服务；缺失时命令的参数形式仍可用，但窗口内插入会失败。

## 风险

DSH 的 `agent-loop-invariant` 要求带 loop 标记的请求与持久化 surface 一致。请求副本不复制该 process-local 标记，因此绕过该校验；这是「只改请求、不改会话」的实现基础，需在真实实例回归。
