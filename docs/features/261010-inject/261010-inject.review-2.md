# dsh-inject 第二轮检视报告

## 概要

本轮检视针对 `dsh-inject` 的最新提交变更，包括：
1. `src/client/*` 前端代码重构（本地草稿 + 300ms 合并写入队列；现场 `InjectDialog` 借助 `createPortal` 挂载；输入栏按钮及设置页 slots 注册）。
2. `src/index.js` 服务端变动：新增 `POST /dsh-inject/turns` HTTP 路由接收现场注入回合；提取会话状态至 `src/session-state.js`；导出 `insertPrefix`。
3. 源文件统一改为 `.js`，`package.json check` 脚本升级。

整体评价：核心领域逻辑（消息替换、构造回合前缀合并与提取消费）设计清晰且测试覆盖完备，但**新增的未授权公开 HTTP 路由存在跨域与权限绕过安全隐患**，以及前端存在若干需要解决的设计与边界问题。

---

## 需求对齐

- **满足度**：满足了快速连续点击「新建预设」不丢失更新、输入栏即时打开注入 dialog、`/inject` 与 `/inject-turn` 会话级控制等核心功能。
- **与计划/设计差异**：现场 dialog 没有使用官方推荐的经由 API Gateway 授权通道（例如 `ctx.remote.commands.execute` 或受信任的 RPC fetch 路由），而是直接在宿主 WebServer 上注册裸 HTTP POST 路由 `/dsh-inject/turns`。

## 阻塞问题

| ID | 位置 | 问题 | 建议 |
|---|---|---|---|
| SEC-01 | [src/index.js:151-168](src/index.js#L151-L168) | **HTTP 路由缺少身份验证与 Host/Origin 防护（CSRF / 未授权投递漏洞）**<br>`POST /dsh-inject/turns` 在 `child.webServer` 上作为裸路由直接注册，未经过 `ctx.connection.admit(req)` 或 `isTrustedApiRequest` 校验。任何同机进程或网络中能访问该 Web 端口的恶意网页均可通过跨站请求（或任意客户端）伪造 POST 请求，向任意活跃会话静默排队注入任意构造消息（包括伪造的 system/user/tool 消息），直接劫持大模型后续对话与工具调用行为。 | **方案 A（推荐）**：遵循 DSH 规范，dialog 直接复用现有的 `/inject-turn` 命令机制，通过前端的 `ctx.remote.commands.execute(sessionId, "/inject-turn " + JSON.stringify(usable), [])` 执行注入，无需单独开 HTTP 路由；<br>**方案 B**：若必须保留自定义 HTTP 路由，请在 `handler` 首行调用 `connection.admit(req)`，非合法授权请求拒绝（返回 401/403）。 |

## 准入结论

**结论**：`不准入`

**说明**：存在阻塞性安全问题（**SEC-01**）：新增的 `POST /dsh-inject/turns` 路由直接暴露在宿主 WebServer 且无任何身份验证与同源校验，存在跨站/未授权注入攻击风险。建议移除裸 HTTP 路由并复用成熟的 `ctx.remote.commands.execute` 执行 `/inject-turn`，或补齐授权防护后重新提审。

# 复审报告（Round 2 复核）

## 概要

本轮针对上一轮提出的 1 项阻塞问题（SEC-01）与 3 项主要建议修改项（SUG-01、SUG-02、SUG-04/队列上限）进行了逐项代码复核，并检查了改动是否引入新问题。全部关键问题均已妥善解决，无新增阻塞或主干风险，达到准入标准。

## 逐项复核结果

1. **SEC-01（`POST /dsh-inject/turns` 鉴权与同源防护）—— 已解决**
   - [src/index.js:146-149](src/index.js#L146-L149) 与 [src/index.js:159-166](src/index.js#L159-L166) 已通过 `ctx.inject(["webServer", "connection"], ...)` 注入 `connection` 服务，并在处理请求首部调用 `child.connection.admit({ headers: req.headers })`。
   - 核查 DSH `@deepseek-ai/dsh-client-connection` 实现：`admit(request)` 接收 `{ headers }`，内部依次执行 `isTrustedApiRequest(request, this.trustedHosts)`（校验 `Host`、`Sec-Fetch-Site`、`Origin`，拦截跨站/DNS Rebinding，失败返回 `403`）和 `this.browserAuth.isAuthenticated(request)`（校验签名 Cookie，未认证返回 `401`）。當 `admission.rejection` 存在时立即返回对应状态码（401/403），防护完整生效。
2. **SUG-01（`InjectDialog` Escape 关闭、自动聚焦与 `createPortal` 评估）—— 已解决**
   - [src/client/inject-dialog.jsx:30](src/client/inject-dialog.jsx#L30) 与 [src/client/inject-dialog.jsx:45-50](src/client/inject-dialog.jsx#L45-L50) 已为首行 `textarea` 绑定 `firstField` ref 并在挂载时自动 `focus()`，同时注册了 `window` 级 `Escape` 键监听关闭弹窗并在卸载时清理。
   - 关于保留 `createPortal(..., document.body)`（[src/client/inject-dialog.jsx:93-124](src/client/inject-dialog.jsx#L93-L124)）：`InjectButton` 挂载于底部 `conversation.input.right` 插槽，若不使用 portal 脱离局部 DOM 层级，全屏模态遮罩易受父级容器 `overflow` / `transform` / 层叠上下文限制（与 `dsh-live-mode` 的 `voice-library.tsx` 原因一致）；且遮罩根节点已带 `.dsh-inject` 作用域类名，CSS 变量使用的是全局 `--dsh-*` 主题变量，因此在此处保留 `createPortal` 完全合理、可接受。
3. **SUG-02（`useLocalConfig` 卸载时未落盘草稿丢失）—— 已解决**
   - [src/client/settings-panel.jsx:31-36](src/client/settings-panel.jsx#L31-L36) 新增了卸载 cleanup effect：当 `timer.current !== null` 时清除定时器并立即调用 `void writeConfig(scope, latest.current).catch(() => undefined)` 将最新草稿刷入宿主，避免了 300ms 防抖窗口内切走页面丢失最后一次修改。
4. **SUG-03 / 原报告 SUG-04（待注入队列无上限）—— 已解决**
   - [src/session-state.js:9](src/session-state.js#L9) 与 [src/session-state.js:38-44](src/session-state.js#L38-L44) 定义了 `MAX_PENDING_TURNS = 200`，超出上限时 `queue()` 返回 `null` 且不修改原队列。
   - 命令端（[src/index.js:88](src/index.js#L88)）返回可读错误提示，HTTP 端（[src/index.js:173](src/index.js#L173)）返回 `429` 状态码，并在 [test/session-state.test.mjs:41-47](test/session-state.test.mjs#L41-L47) 补充了单元测试覆盖。
