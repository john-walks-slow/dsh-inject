# dsh-inject 实施摘要

## 需求

一个 DSH 插件，用于批处理方式管理模型上下文：

- **A 配置页**：多条关键词/正则替换（可按用户/助手/工具返回筛选）、开头构造回合、多预设、可复用模板。
- **B 命令**：会话级启用/禁用预设（默认关闭、可多开、开关零副作用）；在当前位置手动插入构造回合的现场 dialog。

## 关键设计

### 只改请求，不改会话

自动替换实现为 `llm/stream` 上的请求副本改写：请求对象基于会话 surface 派生，插件复制一份、替换其中的文本块后重新派发。原始会话日志与 `session.deriveMessages()` 不变，因此界面显示的始终是用户原文。

副本刻意不带 `markAgentLoopRequest` 的 process-local 标记，从而通过 `agent-loop-invariant` 的「loop 请求必须与持久化 surface 一致」校验。

### 会话级状态与零副作用

启用状态与待注入队列都在 `src/session-state.js` 里，是进程内、按 session id 分区的纯数据结构：默认全空、不写日志、禁用即删除。进程重启后回到默认关闭。

### 请求侧构造回合

预设的「开头构造回合」与手动注入都进入请求前缀，不产生 transcript 事件。`insertPrefix` 保证 system 仍是首条消息（构造的 system 内容与原有 system 合并），`tool` 角色的构造消息转成带标记的用户上下文，避免出现没有对应工具调用的悬空 tool result。

### 现场 dialog

输入 `/inject-turn` 回车打开 modal，可现场增删消息、载入模板、保存模板、插入到当前位置；`Esc` 关闭。投递走宿主 `POST /dsh-inject/turns`，该路由通过 `ctx.connection.admit()` 做 Host/Origin 校验与浏览器鉴权。

输入栏**不放置常驻按钮**：dialog 挂载在 `conversation.input.overlay`，由 `ctx.commandUi.decorate({ name: "inject-turn", ui: { kind: "action" } })` 在裸调用时打开。装饰只接管裸调用，`/inject-turn <模板名|JSON>` 仍走宿主命令处理器。

## 检视结论

两轮检视。第一轮指出 5 项阻塞（配置热更新、写入协议、角色消息、system 位置与工具消息、命令生命周期），修复后第二轮针对安全与健壮性又提出 1 项阻塞（路由鉴权）与 3 项建议，全部修复后第二轮结论为**准入**。
